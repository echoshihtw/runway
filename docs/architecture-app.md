## Executive Summary

`app` is the composition root. It owns almost no logic — its job is to construct the concrete implementations (Drift database, Firebase analytics, RevenueCat purchases), inject them into the `application` layer's placeholder providers via `ProviderScope(overrides:)`, and hand off to `presentation`'s router.

It is also where all platform-specific concerns live: iOS/Android projects, screen-security flags, Firebase config, and app icons.

## Startup Sequence (`main.dart`)

1. `WidgetsFlutterBinding.ensureInitialized()`.
2. **Android only:** `FlutterWindowManagerPlus.addFlags(FLAG_SECURE)` — blocks screenshots and the app-switcher preview. There is no iOS equivalent applied.
3. `Firebase.initializeApp(...)` wrapped in try/catch — **a Firebase failure is logged and ignored**; the app runs without it.
4. Construct `AppDatabase()` and the three `Drift*Repository` instances.
5. `await RevenueCatService.init()`.
6. `runApp(ProviderScope(overrides: [...]))` with five overrides:

| Port | Implementation |
|---|---|
| `analyticsProvider` | `FirebaseAnalyticsService()` |
| `transactionRepositoryProvider` | `DriftTransactionRepository(db)` |
| `loanRepositoryProvider` | `DriftLoanRepository(db)` |
| `subscriptionRepositoryProvider` | `DriftSubscriptionRepository(db)` |
| `purchaseServiceProvider` | `RevenueCatService` |

This is the **only** place where `data` is imported alongside `application` — which is exactly what keeps the layer boundary intact everywhere else.

## `SurvivalApp`

Watches `localeProvider`. While it has no value, it renders a bare themed `Scaffold` (avoids a flash of unstyled content). Once resolved it builds `MaterialApp.router` with `AppTheme.dark`, `appRouter`, and the four localization delegates.

`localeResolutionCallback` prefers the user's saved locale; otherwise it matches the device locale by language+country, then by language alone, and finally falls back to `en`.

## Monetization — RevenueCat (in flight)

`RevenueCatService implements PurchaseService` (`lib/revenuecat_service.dart`):

- `init()` checks `isRevenueCatConfigured` and skips SDK configuration when keys are placeholders — so unconfigured builds degrade to a no-op rather than crashing.
- `fetchOffering()` maps `Offerings.current` to the layer-agnostic `ProOffering`/`ProPackage`; returns `null` on any error.
- `purchasePackage()` casts `ProPackage.nativePackage` back to RevenueCat's `Package`, calls `Purchases.purchase(...)`, and reports success by checking `customerInfo.entitlements.active` for `kProEntitlementId` (`'pro'`). `PurchasesErrorCode.purchaseCancelledError` becomes `PurchaseException(userCancelled: true)`.

**Configuration status (`revenuecat_config.dart`):** the Apple public SDK key is filled in; `kRevenueCatGoogleKey` is still `REVENUECAT_GOOGLE_KEY_PLACEHOLDER`. Because `isRevenueCatConfigured` requires *both* keys to be non-placeholder, **RevenueCat is currently disabled on iOS as well as Android**. Filling in the Android key enables both.

> **Uncommitted work:** `purchases_flutter` v10, `revenuecat_service.dart`, and the RevenueCat config are present in the working tree but not committed as of this scan. The last commits (`ac4738e`, `b87943b`) scaffolded the integration; the current tree carries further changes on top.

## Analytics

`FirebaseAnalyticsService` implements the 12-method `AnalyticsService` port. Only behavioral events are sent — no amounts, balances, or runway values. `NoOpAnalytics` remains the default if the override is absent.

⚠️ **Identifier inconsistency.** Three different values are in play:
- iOS bundle id: `com.silverfern.survivaloptimizer`
- Android applicationId / namespace: `com.survival.app`
- `Makefile` `APP_ID` (used by `make db-reset` / `db-reset-android`): `com.silverfern.survivaloptimizer`
- `.github/workflows/cd.yml` Play Store `packageName`: `com.survival.app`

`make db-reset-android` therefore targets the wrong package on Android. Worth reconciling before store submission.

Icons are generated from the single master `assets/brand/runway-icon-1024.png` via `make gen-icons` (uses macOS `sips` — macOS-only).

## Testing Strategy

- `test/widget_test.dart` — widget-level smoke test.
- `integration_test/smoke_test.dart` + `test_app.dart` — end-to-end, **requires a connected device**:

```bash
cd app && flutter test integration_test/ -d <DEVICE_ID>
```

(The `melos run test:integration:e2e` script in `melos.yaml` is not loaded — melos reads scripts from the root `pubspec.yaml`.)
